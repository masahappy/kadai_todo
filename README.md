AIToDo
AIを活用したタスク管理アプリです。

概要
AIToDoは、日々のタスクを効率的に管理するためのWebアプリケーションです。 「1dayモード」と「1weekモード」を切り替えて使えます。

1dayモード：今日やることを、0〜24時の時間軸に並べて管理します。
1weekモード：締切日つきの課題と今週の予定を管理します。未完了の課題と今週の予定を入力すると、AIが効率的なスケジュールを提案してくれます。
ログイン機能により、ユーザーごとにタスク・予定を管理できます。1dayモードと1weekモードの課題は、完全に分かれて管理されます。

工夫した点
AIアドバイス機能：未完了のタスクと今週の予定・体調をもとに、AIが具体的なスケジュールを提案します。単なるタスク管理にとどまらず、ユーザーの状況に合わせた提案ができる点が特徴です。
セキュアな実装：APIキーをフロントエンドに直接書かず、Cloudflare Workerのサーバーサイドで安全に管理しています。キーはCloudflareの管理画面にだけ登録し、GitHubには置きません。
ユーザーごとのデータ分離：Supabase Authでログイン機能を実装し、user_idとRow Level Security（RLS）により、他人のタスク・予定が一切見えない設計にしました。データベース側にも安全装置を設け、アプリのコード側のミスに対しても二重に守られる構成です。
データの永続化：タスク・予定データをlocalStorageからSupabaseに移行し、デバイスをまたいでも同じアカウントで同じデータにアクセスできる構成にしました。
1day／1weekモードの完全な分離：tasksテーブルにmodeカラムを追加し、モードごとに課題・統計・画面を分けました。テーブルやAPIを複製せずに済むため、保守しやすい構成です。
時間軸の表示：開始・終了時刻から、課題ブロックの位置と高さを計算して配置しています。時間が重なる課題は、カレンダーアプリと同じように、重なりをまとめて列に割り当て、横並びで表示します。
体感速度の改善：課題の追加・完了・削除のたびに全件を取得し直していたため待ち時間が出ていました。画面を先に更新し、保存は裏側で行う方式に変え、保存に失敗したときは元の状態に戻すようにしました。
端末ごとの表示崩れへの対応：LINE内蔵ブラウザで、標準の時刻入力が崩れて見えなくなる問題が起きました。CSSの調整では直らなかったため、時・分のプルダウンに置き換え、どの環境でも同じ見た目・操作になるようにしました。
ホスティングの移行（Netlify → Cloudflare）：Netlifyのクレジット上限で本番デプロイが止まったため、Cloudflare Workersに移行しました。7つあったAPI（Netlify Functions）を1つのWorkerにまとめ、画面の通信先も/api/に置き換えました。移行は別ブランチ（cloudflare）で進め、動作確認ができるまで元の公開サイトを残すことで、止めずに切り替えられるようにしました。
苦労した点
AIの実装にあたっての試行錯誤。APIキーの安全な管理方法や、利用モデルの廃止（Groqのモデル廃止）への対応など、多くの課題を一つひとつ解決しながら開発を進めました。
localStorageからSupabaseへのデータ移行に伴う、CRUD処理の全面的な書き換え。
ログイン機能の導入に伴い、サーバー側でユーザーの認証トークンを検証する共通処理を新たに設計し、既存の全APIエンドポイントに組み込む必要がありました。
1day／1weekモードを分けたことで、絞り込みの漏れ（統計に他のモードの課題が混ざる、など）や、処理の途中終了による表示の不具合が起きました。原因を一つずつ切り分けて直しました。
LINE内蔵ブラウザなど、ブラウザごとに時刻入力の表示が異なる問題。ブラウザ標準の部品に頼らない作りに変えることで解決しました。
時間が重なる課題を、読みやすく並べるアルゴリズムの設計。
Cloudflareへの移行で、ビルドが「成功」と表示されたのに画面が出ない問題が起きました。原因は、自動ビルドの対象ブランチがmainのままで、Workerのコードが入っていなかったことでした。ビルドのログや設定画面を順に確認して、原因を切り分けました。
ログインで「Failed to fetch」が出た際、コードではなく、Supabaseの無料プランのプロジェクトが一時停止していたことが原因でした。通信エラーのときは、コードだけでなく、外部サービスの状態も確認する必要があると学びました。
